<a name="guide-title"></a>
# データセット診断

**SDXL**・**Anima**・**MOSS-Image** に対応しています（Krea 2 / `musubi-tuner` は `loss.jsonl` を出力しません）。

学習の各ステップではサンプルごとにランダムなノイズタイムステップが抽選され、生の損失（Loss）はノイズ帯によって数倍の差が出ます。たまたま損失の高いタイムステップが多く当たっただけで平均 Loss が高く見えるため、生の Loss では画像同士を公平に比較できません。本機能は Kohya `sd-scripts` のサンプル別残差分析（上流文書 [`loss.jsonl` と残差分析](https://github.com/kohya-ss/sd-scripts/blob/v0.13.1/docs/run_control.md#analyzing-the-loss-log--loss-%E3%83%AD%E3%82%B0%E3%81%AE%E5%88%86%E6%9E%90) 参照）に基づき、各サンプルを**近いタイムステップ区間**の中で比較します。

- **残差（相対的な難易度）**：同じタイムステップ区間の平均損失に対する各サンプル損失の相対差です。`0%` がデータセット平均で、正の値が大きいほど学習しにくく、負の値が小さいほど学習しやすいことを示します。
- **エポックあたりの傾き（残差が収束しているか）**：比較可能なエポックが `3` 回以上そろった後、同エポックの他画像に対する残差の変化速度を示します。負の値は全体平均との差が縮まっている状態、`0%` 付近や正の値は下げ止まりを示します。

いずれも**同一の学習実行内**での相対評価です。モデル全体の仕上がりはチェックポイントの生成プレビューとあわせて判断してください。

<a name="rules"></a>
## 状態サインと対処の目安

画面上部の**最小サンプル**（既定は比較可能サンプル `3` 回以上）・残差 `±20%`・動的な**低下傾きしきい値**に基づき、上から優先順で 6 つの状態に自動分類します。

| 状態サイン | 判定条件（上から順に優先一致） | 主な原因と推奨アクション |
| --- | --- | --- |
| `NaN / Inf` | 非有限の Loss を記録 | ごく一部の画像ならファイル破損や異常な色空間を確認。広範囲で発生した場合は学習率と混合精度を直ちに見直す |
| `集計待ち` | 有効サンプル数または同区間の比較対象 `< 最小サンプル`（詳細は**サンプル不足 / 比較対象不足**） | エポックが進んでサンプルが貯まるまで待つか、ヘッダの**最小サンプル**を一時的に下げて傾向を確認 |
| `高残差（要確認）` | 残差 `≥ +20%`、かつ 3 エポック未満または傾きが低下しきい値に未達（詳細は**要確認 / 未低下 / 微減**） | 平均より高いまま下がらない状態。タグ漏れ・誤記・破損画像・不適切なトリミング・画風の競合が多いため、詳細モーダルで元画像とキャプションを確認し、個別 `.txt` は**タグ編集で開く**から修正 |
| `高残差（低下中）` | 残差 `≥ +20%`、かつ傾き `≤ 低下傾きしきい値` | 構図や衣装が複雑だがモデルは着実に吸収中。除外せず後続エポックの推移を観察 |
| `平均より低い` | 残差 `≤ -20%` | 単調な構図や類似・重複画像。該当画像が極端に多い場合はプレビューで過学習を確認し、重複の削減を検討 |
| `平均付近` | `-20% < 残差 < +20%` | データセット全体の進行と一致しており、個別の対処は不要 |

補足：低下傾きしきい値は各画像の比較可能なエポック幅に応じて `-2.0%〜-0.4% / エポック` の範囲で自動換算されます（計算式は下の[同エポック・同区間基準の傾き](#slope)を参照）。確認時は散布図の外れ値や一覧ソートと併用して上位から点検してください。

<a name="workflow"></a>
## 確認手順とパネルの連携

1. **「概要」タブで個別画像の問題かグループ全体の偏りかを切り分ける**
   - **左欄の散布図**：3 エポック未満は残差の 1 次元分布、3 エポック到達後は**残差 × 傾き**の 2 次元散布図になります。チャート右上の**領域着色**をオンにし、右上または右下の色付き領域をクリックすると、`高残差（要確認）` または `高残差（低下中）` の画像を一括選択できます（画像ごとにしきい値が異なる場合は両領域の間に余白ができ、点の色で状態を判別できます）。点をクリックするとプレビューカードを固定し、詳細モーダルを開けます。
   - **右欄 ① 画像の状態分布**：6 状態の枚数を一覧表示し、行をクリックすると散布図とタイムステップ曲線を絞り込めます。
   - **右欄 ② タイムステップ区間（`1000 → 0`）**：ノイズ除去の進行順（左が高ノイズ `1000`、右が低ノイズ `0`）で 18 区間の平均 Loss・高/中/低ノイズのサンプル比率・破線の理論分布を表示します。状態・グループ・個別画像にホバーまたは選択すると比較曲線が重なり、偏りのあるノイズ帯から原因を絞り込めます：
     - **左側の高ノイズ帯（大まかな構図・配色段階）が高い**：白背景の立ち絵と複雑な背景画像の混在、大きな余白パディング、極端なトリミング差が主因です。背景タグの補完、バケット設定、サブセットのタイムステップオフセットを見直してください。
     - **右側の低ノイズ帯（細部の質感・描き込み段階）が高い**：ピンぼけ・過度な拡大・JPEG ブロックノイズ・スクリーントーンのモアレ・透かしや文字残りが主因です。該当する低品質画像の差し替えや除外を検討してください。
   - **右欄 ③ グループ比較**：**サブセット / フォルダ / バケットサイズ / バッチサイズ**別に平均残差と傾きを集計します（フォルダがサブセットと完全に同一の場合や、項目が 1 つしかない軸は自動で非表示になります）。特定グループ全体が高い場合は `num_repeats`・タグ付け基準・トリミング位置を確認し、行クリックで概要チャートを絞り込むか、行末の **`↗`** から**画像別の確認**タブへ直接移動して該当画像を点検します。
2. **詳細モーダルでトリミング位置と適用キャプションを照合する**
   - 左側で `元画像 → バケット` の解像度とトリミング／拡大率を確認し、主要な被写体の見切れや過度な引き伸ばしがないかチェックします。
   - 右側でエポック別の残差推移、全体平均に対する各タイムステップのサンプル位置、現在適用されているキャプション全文を確認します。
3. **ヘッダの対象範囲と再開時の実行区間**
   - **データセット範囲**：正則化画像がある場合、学習画像の平均基準が歪まないよう既定で**学習データのみ**が選ばれます（必要に応じて**正則化データのみ / すべてのデータセット**へ切替可能）。
   - **実行（記録区間）**：同じ出力先フォルダと名前で再実行すると、同一の `loss.jsonl` に新しい区間が追記されます。**途中再開（Resume）**時はヘッダの**実行**で**全 {n} 回の実行を統合**を選んで傾きを連続集計し、**同名で最初から再学習**した場合は既定の**最新**のままにします。

<a name="residual"></a>
## 算出仕様と上流との違い

本ツールは `sd-scripts` の `--run_control` が書き出す `loss.jsonl` を読み取り、上流の [`tools/analyze_run_loss.py`](https://github.com/kohya-ss/sd-scripts/blob/v0.13.1/tools/analyze_run_loss.py) に対して次の拡張を加えています。

<a name="residual-bins"></a>
### 残差の基準（10 等分区間）

観測されたタイムステップ範囲を 10 等分し、同じ区間に **2 枚以上の異なる画像**が存在する場合のみ比較基準を作ります（タイムステップ欠損や区間内に 1 枚しかないサンプルは平均 Loss と総サンプル数にのみ計上）：

<div class="doc-equation" role="group" aria-label="サンプル残差の計算式">
  <div class="doc-equation-kicker">サンプルの残差</div>
  <div class="doc-equation-expression">残差 = サンプル損失 ÷ 同タイムステップ区間の平均損失 − 1</div>
  <p>画像やグループの残差は、比較可能な全サンプル残差の算術平均です（<code>0%</code> が平均、正は難、負は易）。</p>
</div>

<a name="slope"></a>
### 同エポック・同区間基準の傾きとスパン別しきい値

全体の Loss 低下トレンドが傾きに混ざるのを防ぐため、**同じエポック・同じタイムステップ区間の他画像の平均損失**（`> 0`）を基準にエポック別の残差を出し、`3` エポック以上そろった時点で最小二乗法により傾きを算出します。

`高残差（低下中）` の判定に使う**低下傾きしきい値**は、その画像の最初と最後の比較可能エポック幅（`span`）に応じて決まります。

- `span ≤ 5`（連続 `6` エポック以下）：**`-2.0% / エポック`**；
- `5 < span < 25`：そのスパンで**累計 `10%` 以上の低下**に相当する傾き（`-10% / span`）へ自動換算；
- `span ≥ 25`：下限 **`-0.4% / エポック`** に固定し、長期学習で緩やかに改善している画像が停滞と誤判定されるのを防ぎます。

<a name="timestep-deweighting"></a>
### タイムステップ重みの復元と書出間隔

- **タイムステップ重みの除去**：`loss.jsonl` の `loss` には `--weighting_scheme`（[タイムステップ](timesteps.ja-JP.md#weighting)参照）とマスク重みが含まれ、サンプル別の `loss_weight`（`--prior_loss_weight` など）や `--min_snr_gamma` は含まれません。**Anima** と **MOSS-Image** で `sigma_sqrt` または `cosmap` を使用している場合、タイムステップ重みで割り戻して未重み付け Loss を復元してから区間平均と残差を算出します。
- **書出間隔とマルチ GPU**：約 5 秒ごとに `status.json` とあわせて書き出され、マルチ GPU 学習ではメインプロセス（rank 0）のサンプルのみ記録されます。各フィールドの定義は上流文書 [`run_control.md#lossjsonl`](https://github.com/kohya-ss/sd-scripts/blob/v0.13.1/docs/run_control.md#lossjsonl) を参照してください。
