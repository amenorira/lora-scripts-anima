<a name="guide-title"></a>
# データセット診断

**SDXL**・**Anima**・**MOSS-Image** に対応しています（Krea 2 / `musubi-tuner` は `loss.jsonl` を出力しません）。

学習の各ステップではサンプルごとにランダムなタイムステップが抽出（サンプリング）され、生の損失（Loss）はノイズ帯によって数倍の差が出ます。本機能は Kohya `sd-scripts` のサンプル別残差分析（上流文書 [`loss.jsonl` と残差分析](https://github.com/kohya-ss/sd-scripts/blob/v0.13.1/docs/run_control.md#analyzing-the-loss-log--loss-%E3%83%AD%E3%82%B0%E3%81%AE%E5%88%86%E6%9E%90) 参照）に基づき、各サンプルを**近いタイムステップ区間**の中で比較します。

| 主要指標 | 意味 | 見方の目安 |
| --- | --- | --- |
| **残差** | 同じタイムステップ区間の平均損失に対する相対差 | `0%` が全体平均。正は難しく、負は易しい |
| **エポックあたりの傾き** | 比較可能なエポックが `3` 回以上そろった後の、同エポック他画像基準に対する残差の変化速度 | 負は平均との差が縮小中、`0%` 付近は横ばい、正は残差上昇（差が拡大） |

残差は同じ学習内での相対差です（全体の加重平均は常に `0%`）。たとえば 40 枚のキャラクターデータセットに、単色背景の立ち絵 30 枚と複雑な背景イラスト 10 枚を混ぜた例を示します。

| サンプル種別 | 初期の平均損失（全体平均 `0.178`） | 8 エポック目の平均損失（全体平均 `0.143`） | 変化の意味 |
| --- | --- | --- | --- |
| 単色背景の立ち絵（30 枚） | `0.15`（残差 `-15.5%`） | `0.12`（残差 `-15.8%`） | 損失は約 20% 低下、相対位置は不変 |
| 複雑な背景イラスト（10 枚） | `0.26`（残差 `+46.5%`） | `0.21`（残差 `+47.4%`） | 同じく約 20% 低下しているが、残差は高いまま傾きが `0%` 付近になる |

> 残差と傾きはいずれも同一の学習実行内での相対評価です。モデル全体の仕上がりや過学習の有無は、チェックポイントの生成プレビューとあわせて判断してください。

<a name="rules"></a>
## 状態サインと判定条件

画面上部の**最小サンプル**（既定は比較可能サンプル `3` 回以上）・残差 `±20%`・動的な**低下傾きしきい値**に基づき、優先順で 6 つの状態に自動分類します（UI の表示順に掲載）。

| 状態サイン | 判定条件 | 確認の目安 |
| --- | --- | --- |
| `NaN / Inf` | NaN / Inf（非有限値）の損失を記録 | ごく一部の画像ならファイル破損や異常な色空間を確認。広範囲で発生した場合は学習率と混合精度を直ちに見直す |
| `高残差（未低下）` | 残差 `≥ +20%`、かつ比較可能 3 エポック未満または傾き `> 低下傾きしきい値` | 任意の 1 枚でも 3 エポックに達すると概要欄はすべてこの名称に切り替わり、個別表示では傾き未算出が**高残差**、わずかに低下中（`< 0`）が**高残差（微減）**、横ばい・上昇中（`≥ 0`）が**高残差（未低下）**となる。下表で元画像・トリミング・キャプションを確認 |
| `高残差（低下中）` | 残差 `≥ +20%`、かつ傾き `≤ 低下傾きしきい値` | 構図や衣装が複雑だがモデルは着実に吸収中。除外せず後続エポックの推移を観察 |
| `平均付近` | `-20% < 残差 < +20%` | データセット全体の進行と一致しており、個別の対処は不要 |
| `低残差` | 残差 `≤ -20%` | 単純な構図・ベースモデルに近い画風・類似画像に多い。緑色の表示は学習しやすさを示すのみで、該当画像が極端に多い場合はプレビューで過学習を確認 |
| `集計待ち` | 有効サンプル数または比較可能サンプル数が**最小サンプル**未満（個別画像のバッジ表示は**サンプル不足**／**比較対象不足**） | サンプルが集まるまで待つか、ヘッダの**最小サンプル**を一時的に下げる |

補足：`NaN / Inf` と `集計待ち` は残差のしきい値より優先して判定されます。低下傾きしきい値は各画像の比較可能なエポック幅に応じて `-2.0%〜-0.4% / エポック` の範囲で自動調整されます（下の[同エポック・同区間基準の傾き](#slope)を参照）。

<a name="diagnosis"></a>
## 高残差と低残差の読み方

### 高残差でよくある 4 つのケース

高残差の画像を詳細モーダルで開き、**傾き・タイムステップ曲線（左が高ノイズ / 右が低ノイズ）・トリミング率・キャプション**を合わせて確認します。

| ケースと具体例 | パネル上の特徴 | 背景と対処 |
| --- | --- | --- |
| **タグ漏れ・内容の矛盾**<br>目立つ赤い眼鏡や 2 人目の人物が描かれているのに `.txt` が `1girl, solo` のみ、または複雑な背景のタグが抜けている | 残差が大幅に高く（例：`+30%〜+60%`）、比較可能 3 エポック以降も傾きが横ばいまたは上昇。タイムステップ曲線の**左側・中央（高ノイズの構図域・中ノイズの構造域）**が全体曲線より高い | テキスト条件と画像内容が矛盾し、モデルが相反する教師信号を学習させられるため。詳細モーダルで元画像とタグを照合し、**タグ編集で開く**から不足タグ補完や矛盾の修正を行う |
| **ぼやけ・圧縮ノイズ・透かし**<br>低解像度の無理な拡大、強い JPEG ブロックノイズ、網点モアレ、隅の文字や透かし | 残差が高いまま下がらない。タイムステップ曲線の**右側（低ノイズの細部・質感域、`t` が `0` 付近）**だけ跳ね上がり、左側は平均付近 | 低ノイズ帯は高周波の細部を復元する段階であり、ランダムなノイズや圧縮劣化には規則性がなく損失が下がらないため。高画質な元画像へ差し替えるか、透かしのトリミング・低品質画像の除外を検討 |
| **バケットのトリミングで被写体が切れている**<br>縦長の全身絵が正方形寄りのバケットに入り、タグに `boots, standing` があるのに下半身が切れている | 詳細モーダル左側の `元画像 → バケット` のトリミング率が大きい、または右欄の**バケットサイズ**で特定比率全体が高い（上部に**トリミング差**が表示される場合あり） | タグに書かれた対象が枠外に切り落とされ、画像とキャプションの不一致になっているため。バケットの許容縦横比を広げるか解像度ステップを細かくする、あるいは事前に手動トリミングして切れた部位のタグを削除 |
| **複雑な構図 / 希少なアングル**<br>強いあおり構図、装飾の多い衣装や鎧、描き込みの多い背景で、データセット内で少数派の画像 | 残差 `+20%〜+40%`。比較可能 3 エポック到達後は**高残差（低下中）**になりやすく、中盤以降は全体の低下と歩調を合わせて傾きが `0%` 付近に落ち着く。元画像は鮮明でトリミング・キャプションも正確 | 画像自体の情報量がデータセット平均より多いか、その構図の出現頻度が低いため。**元画像を残す**。この種の構図をよりしっかり学ばせたい場合は類似画像を追加するか、該当サブセットの `num_repeats` を少し上げる |

### 低残差でよくある 3 つのケース

| ケースと具体例 | パネル上の特徴 | 背景と対処 |
| --- | --- | --- |
| **シンプル・単色背景の構図**<br>白背景の三面図、無地の空、背景が大きくボケたアップ | ごく一部の単純な画像だけが低残差に入り、大半は `0%` 付近に分布 | 広い平坦部分は細部が少なく、どのノイズ帯でも予測しやすいため損失が自然に低くなる。正常な傾向のため対処不要 |
| **類似・重複画像、または繰り返し回数過多**<br>同じポーズの連写 6 枚、ほぼ同じ下絵の表情差分 5 枚、または特定サブセットだけ `num_repeats` が極端に多い | 残差が `-30%〜-50%` に急落し、他の通常画像が相対的に押し上げられる | モデルが固定ピクセルをそのまま暗記しやすく、構図の固定化やポーズ崩れを招くため。重複画像を間引くか該当サブセットの `num_repeats` を下げ、プレビューで汎化性を確認 |
| **ベースモデルの素の画風に近い**<br>アニメ系ベースモデルでの画風 LoRA 学習に、素の画風に近い標準的なバストアップが多数混在 | 多くの画像が低残差に寄り、プレビューでの画風変化が弱い | ベースモデルが元々低い誤差でノイズ除去できるため LoRA が重みをほぼ更新せず、画風を寄せる効果が弱くなるため。目標画風の特徴がはっきり出た学習画像を追加 |

### 学習段階ごとの見るポイント

| 学習段階 | データの傾向 | 注目するポイント |
| --- | --- | --- |
| **初期**（比較可能 `3` エポック未満、または 1 枚あたり `5` サンプル未満） | ランダムなタイムステップとノイズによるばらつきが大きく、傾きは未算出 | 破損画像・空キャプション・`NaN / Inf` など極端な外れ値だけを確認し、この段階で大量に削除しない |
| **中期**（目安 `3〜10` エポック） | 傾きが安定し、`高残差（低下中）` と `高残差（未低下）` を最も切り分けやすい | 高残差（未低下）に留まる画像を重点確認し、タグ不備・トリミングずれ・低画質を修正 |
| **後期**（長期学習、例：`15+` エポック） | 全体の損失が落ち着き、傾きが総じて `0%` 付近に収束 | それまで平均付近だった画像群が大きく低残差へ沈んでいないか確認し、プレビューと合わせて早期終了や過去チェックポイント採用を判断 |

### 運用上の注意点

- **実行中のタグ編集・画像削除は即座に反映されない**：Text Encoder 出力キャッシュ（Anima / MOSS-Image の既定）や Latent キャッシュを有効にしている場合、学習中に `.txt` や画像を編集しても実行中の学習には反映されません。キャッシュなし構成で実行中に画像を削除すると読み込みエラーの原因になるため、修正後は停止して再キャッシュ・再学習してください。
- **データ拡張やマスク重みによるばらつき**：`caption_dropout_rate`・`shuffle_caption`・`random_crop`・`color_aug` を使うとステップごとの損失変動が大きくなるため、**最小サンプル**を `5` や `10` に上げるか複数エポック待ってから判断してください。`masked_loss` 使用時は、マスク面積比の違いによって残差に系統的な偏りが出ることがあります。
- **2 次元散布図の点数が状態集計より少なくなる場合**：3 エポック到達後の 2 次元散布図は `最小サンプル以上` かつ傾き算出済みの画像のみ描画します。`NaN / Inf` や比較可能 `3` エポック未満の画像は**画像別の確認**で確認してください。

<a name="workflow"></a>
## パネル領域と連携操作

| パネル領域 | 表示内容と操作方法 |
| --- | --- |
| **ヘッダ · 表示切替と集計範囲** | 左側で**概要 / 画像別の確認**を切り替え、右側で**最小サンプル**（`1 / 3 / 5 / 10`）・**データセット**範囲・**実行**区間を選択。正則化画像がある場合は学習基準の歪みを防ぐため既定で**学習データのみ**を選択（**正則化データのみ / すべてのデータセット**へ切替可）。同一出力先で再実行すると `loss.jsonl` に追記されるため、**途中再開（Resume）**時は**全 N 回の実行を統合**を選び、**同名で最初から再学習**した場合は既定の**最新（実行 ID）**のまま維持 |
| **概要上部 · 診断サマリーバー** | 現在の状態要約（`NaN / Inf`・高残差サマリー・安定表示）と、該当一覧へのジャンプボタン・注目グループのチップを表示 |
| **左欄 · 散布図** | 比較可能 3 エポック未満は残差の 1 次元分布、到達後は**残差 × 傾き**の 2 次元散布図を表示。右上の**領域着色**をオンにし、右上または右下の色付き領域をクリックすると**高残差（未低下）**または**高残差（低下中）**を一括選択可能。点をクリックしてプレビューカードを固定し、サムネイルクリックで詳細モーダルを表示 |
| **右欄 ① · 画像の状態分布** | 6 状態の枚数を一覧表示し、行クリックで散布図とタイムステップ曲線を連動絞り込み |
| **右欄 ② · タイムステップ区間（`1000 → 0`）** | ノイズ除去の進行順（左が高ノイズ `1000` → 右が低ノイズ `0`）で 18 区間の**平均損失**・高/中/低ノイズ比率・破線の**理論分布**を表示。状態・グループ・個別画像のホバーまたは選択で比較曲線を重ね表示 |
| **右欄 ③ · グループ別集計** | **サブセット / フォルダ / バケットサイズ / バッチサイズ**別に平均残差を集計（フォルダがサブセットと完全に一致する場合や 1 件のみの軸は自動で非表示、**バケットサイズ**では縦横比差が `4%` 以上で**トリミング差**を表示）。前 3 軸は傾き表示・クリック絞り込み・行末 **`↗`** での**画像別の確認**遷移に対応し、**バッチサイズ**はホバー比較のみ（傾き・クリック絞り込み・`↗` なし） |
| **詳細モーダル** | 左側で `元画像 → バケット` の解像度とトリミング `%`／拡大率 `×` を照合し、右側でエポック別残差推移・タイムステップ別サンプル位置・ディスクから読み込んだ**キャプション**（または**サブセットのクラストークン**）を確認 |

<a name="residual"></a>
## 算出仕様と上流との違い

本ツールは `sd-scripts` の `--run_control` が書き出す `loss.jsonl` を読み取り、上流の [`tools/analyze_run_loss.py`](https://github.com/kohya-ss/sd-scripts/blob/v0.13.1/tools/analyze_run_loss.py) に対して次の拡張を加えています。

<a name="residual-bins"></a>
### 残差の基準（10 等分区間）

観測されたタイムステップ範囲を 10 等分し、同じ区間に **2 枚以上の異なる画像**が存在する場合のみ比較基準を作ります（タイムステップ欠損や区間内に 1 枚しかないサンプルは平均損失と総サンプル数にのみ計上）。

<div class="doc-equation" role="group" aria-label="サンプル残差の計算式">
  <div class="doc-equation-kicker">サンプルの残差</div>
  <div class="doc-equation-expression">残差 = サンプル損失 ÷ 同タイムステップ区間の平均損失 − 1</div>
  <p>画像やグループの残差は、比較可能な全サンプル残差の算術平均です（<code>0%</code> が平均、正は難しく、負は易しい）。</p>
</div>

<a name="slope"></a>
### 同エポック・同区間基準の傾きとスパン別しきい値

全体の損失低下トレンドが傾きに混ざるのを防ぐため、**同じエポック・同じタイムステップ区間の他画像の平均損失**（`> 0`）を基準にエポック別の残差を出し、`3` エポック以上そろった時点で最小二乗法により傾きを算出します。`高残差（低下中）` の判定に使う**低下傾きしきい値**は、最初と最後の比較可能エポックの差（`span = 最終 − 最初`）に応じて決まります。

| 比較可能エポック幅（`span`） | 低下傾きしきい値 | 補足 |
| --- | --- | --- |
| `span ≤ 5`（連続 `6` エポック以下） | `-2.0% / エポック` | 短期学習では明確な低下幅を要求 |
| `5 < span < 25` | `-10% / span` | スパン内で累計 `10%` 以上の低下になる傾きを自動算出 |
| `span ≥ 25` | `-0.4% / エポック` | 長期学習で緩やかに改善中の画像を停滞と誤判定しない下限 |

<a name="timestep-deweighting"></a>
### タイムステップ重みの除去と書き出し間隔

- **タイムステップ重みの除去**：`loss.jsonl` の `loss` には `--weighting_scheme`（[タイムステップ](timesteps.ja-JP.md#weighting)参照）とマスク重みが含まれ、サンプル別の `loss_weight`（`--prior_loss_weight` など）や `--min_snr_gamma` は含まれません。**Anima** と **MOSS-Image** で `sigma_sqrt` または `cosmap` を使用している場合、タイムステップ重みで割り戻して重み付け前の損失を復元してから区間平均と残差を算出します。
- **書き出し間隔とマルチ GPU**：約 5 秒ごとに `status.json` とあわせて書き出され、マルチ GPU 学習ではメインプロセス（rank 0）のサンプルのみ記録されます。各フィールドの定義は上流文書 [`run_control.md#lossjsonl`](https://github.com/kohya-ss/sd-scripts/blob/v0.13.1/docs/run_control.md#lossjsonl) を参照してください。
