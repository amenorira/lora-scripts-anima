# データセット診断

データセット診断は、学習中に記録されたサンプル別ログ `loss.jsonl` を集計し、画像ごと・グループごとの**残差（同ノイズ帯比）**と**傾き（エポックあたりの変化）**を算出して、キャプションの不一致、問題のある画像、サブセットやバケットの偏りを特定する機能です。

対応プロファイル：**SDXL**・**Anima**・**MOSS-Image**（Krea 2 / `musubi-tuner` は `loss.jsonl` の記録に未対応です）。

残差と傾きは**同一学習ランの中での画像間の相対的な難易度**を比較します。学習全体の収束具合は、保存された複数チェックポイントの生成サンプルをあわせて確認してください。

## 残差：同じノイズ強度どうしで比較する

各学習ステップではサンプルごとにランダムなノイズのタイムステップが割り当てられます。サンプルの損失はタイムステップ（ノイズの強さ）に強く依存し、たとえばあるタイムステップではどの画像も `0.35` 前後、別のタイムステップでは `0.15` 前後になります。このとき `0.30` という損失は後者では高く、前者では低い値です。たまたま損失の高いタイムステップを多く引いた画像が「難しい画像」に見えてしまうため、生の損失そのままではサンプル間や画像間で比較できません。

そこで、「同じくらいのノイズ強度の他サンプルと比べて、この損失はどのくらい高いか」を表す**残差（Residual）**を使います。

1. 観測されたタイムステップの範囲を **10 等分のタイムステップ区間**に分け、区間ごとに全サンプルの平均損失を求めます。
2. 各サンプルの残差を次の式で求め、画像ごと（またはグループごと）に比較可能なサンプル残差の平均をとります。

<div class="doc-equation" role="group" aria-label="サンプル残差の計算式">
  <div class="doc-equation-kicker">サンプルの残差</div>
  <div class="doc-equation-expression">残差 = サンプル損失 ÷ 同じタイムステップ区間の平均損失 − 1</div>
  <p>画像やグループの残差は、比較可能なサンプル残差の平均値です。</p>
</div>

| 残差 | 意味 |
| --- | --- |
| `0%` | 同じノイズ区間の全体平均と同じ |
| `+50%` | 同じノイズ区間の平均より 50% 高い（他より難しい） |
| `-20%` | 同じノイズ区間の平均より 20% 低い（他より易しい） |

たとえば、ある区間の平均損失が `0.20` のとき、その区間で損失が `0.30` だったサンプルの残差は `0.30 ÷ 0.20 - 1 = +50%` です。

同じタイムステップ区間に 2 枚以上の異なる画像が含まれている場合に比較が成立します。タイムステップが不明なサンプルや、同じ区間に他の画像がないサンプルは「元の平均損失」と総サンプル数にのみ集計されます。比較可能なサンプル数が上部の「最小サンプル」未満の画像は`サンプル不足`または`比較対象不足`となります。

## 傾き：複数エポックの推移を見る

複雑な構図、珍しい被写体、ベースモデルと離れた画風などは、学習初期の残差が高くなりやすく、学習が進むにつれてエポックごとに下がっていきます。エポックを重ねても残差が高いまま下がらない画像は、画像やキャプション自体に問題がある可能性を示します。

同じ画像に比較可能なサンプルが **3 エポック以上**記録されると、各エポックの平均残差に対して最小二乗法で直線を当てはめ、1 エポックあたりの残差の変化量である**傾き（Slope）**を算出します（2 エポックのみではばらつきが大きいため算出されません）。
- たとえば平均残差が Epoch 1 の `+30%` から Epoch 3 の `+20%` へ下がった場合、傾きは約 `-5.0%` / Epoch です。

残差と傾きを組み合わせた確認の目安：

| 見られる傾向 | 主な原因 | 確認・対応の目安 |
| --- | --- | --- |
| 高残差（`≥ +20%`）だが傾きが負（`≤ -2.0%` / Epoch） | 複雑な構図や未知の特徴をモデルが学習している途中 | 除外せず、次のエポックの推移を観察 |
| 高残差（`≥ +20%`）のまま横ばいまたは上昇（`> -2.0%` / Epoch） | キャプションの不一致・タグ欠落、トリミング不備、画質劣化、または他画像との定義の衝突 | **詳細モーダルで元画像とキャプションを確認**し、必要に応じてタグエディタで修正 |
| 残差が常に低い（`≤ -20%`） | 単調な背景、易しい被写体、重複・酷似画像が多い | 少数なら正常。多数が極端に低い場合は生成サンプルで過学習を確認 |
| サンプル数が少ない／3 エポック未満 | 各画像は 1 エポックに `1 × repeats` 回だけランダムなタイムステップとノイズで学習されるため、初期はばらつきが大きい | 上部の**最小サンプル**を増やすか、3 エポック以上進んでから判断 |

## 画面の連携と確認手順

1. **最初に `NaN / Inf` の異常損失を確認する**
   - 非有限（`NaN` / `Inf`）の損失が記録された画像は最優先で先頭に表示され、詳細モーダルの上部に最初の異常が発生した `Epoch`・`Step`・タイムステップ `t` を示します。
   - 特定の画像に集中する場合は画像ファイルの破損、ビット深度、色空間を確認してください。多くの画像で発生する場合は学習率、混合精度、数値安定性の設定を見直します。

2. **「分布とグループ」で全体の偏りを把握する**
   - **画像分布チャート**：3 エポック未満では残差の分布ヒストグラムと画像ごとの点を表示し、3 エポック以降は「横軸：残差 × 縦軸：傾き」の散布図に切り替わります。右上の強調領域が高残差かつ低下が遅い（または未低下の）要確認サンプルです。点にカーソルを合わせるとサムネイルと指標をプレビューでき、クリックで詳細モーダルを開きます。
   - **ノイズ帯域チャート（`1000 → 0`）**：生成時のノイズ除去順に左（`1000`、高ノイズ）から右（`0`、低ノイズ）へ 10 区間の全体平均損失と、高（`1000–667`）・中（`667–333`）・低（`333–0`）の 3 帯域のサンプル数・割合を表示します。残差は各区間の平均損失を基準とするため、全体のサンプル数が極端に少ない帯域では残差のばらつきも大きくなります。
   - **グループ比較**：**バケットサイズ**・**サブセット**・**フォルダ**の各行をクリックすると、下の画像一覧をそのグループで絞り込めます。特定バケット全体の残差が高い場合はトリミングやアスペクト比を、特定サブセットやフォルダ全体の残差が高い場合は `num_repeats`、`class_tokens`、キャプション品質を確認してください。**バッチサイズ**は端数バッチなどバッチサイズ別の平均比較用です。

3. **詳細モーダルでの照合とキャプション編集**
   - 画像をクリックすると詳細モーダルが開き、右側に高・中・低ノイズ帯別の残差、**エポック別の残差推移**、**タイムステップ別損失**（全体平均の基準線にその画像の各サンプルを重ね、全ノイズ帯で一様に高いのか特定サンプルの偏りかを判別できます。各帯域のサンプル数もあわせて確認してください）を表示します。
   - 下部にはサブセット設定から特定されたキャプションファイル、メタデータの記述、または `class_tokens` を表示します。独立したローカルのキャプションファイルであれば、**タグエディタで開く**から直接編集画面へ移動できます。

4. **区間の切り替えと正則化画像の絞り込み**
   - **区間**：同じ出力フォルダと出力名で学習を再度開始すると、`loss.jsonl` の末尾に新しい `run_id` の区間が追記されます。**学習を再開（Resume）した場合**は、上部の「区間」で**全区間をまとめる**を選ぶと通算のサンプル数と傾きを確認できます。**同じ出力名で最初からやり直した場合**は、前回の古い記録が混ざらないよう既定の**最新**区間のみを表示してください。
   - **正則化画像**：正則化画像を含むランでは、一覧のツールバーで**正則化画像を含める / 正則化画像を除外 / 正則化画像のみ**を切り替えて、学習画像と正則化画像を分けて比較できます。

## 状態分類基準とログの記録仕様

### 画面上の状態分類基準

上流の `analyze_run_loss.py` は残差の順で並べるのみで固定のしきい値を持ちません。本画面では上部の**最小サンプル**（既定 `≥ 3` 回の比較可能サンプル）に基づき、次の優先順で状態を分類します。絞り込みバーの **`高残差(要確認)`** は 3 つの高残差状態をまとめて対象にします。

| 絞り込みカテゴリ | カード / テーブルの状態バッジ | 判定条件（上から順に優先評価） |
| --- | --- | --- |
| `NaN / Inf` | `NaN / Inf` | 非有限（`NaN` / `Inf`）の損失が 1 回以上記録された |
| — | `サンプル不足` | 有限損失の総サンプル数 `< 最小サンプル` |
| — | `比較対象不足` | 総サンプル数は基準以上だが、同区間に他画像がある比較可能サンプル数 `< 最小サンプル` |
| `高残差(要確認)` | `高残差(要確認)` | 比較可能サンプルが基準以上、残差 `≥ +20%`、かつ比較可能エポック `< 3`（傾き未算出） |
| `高残差(要確認)` | `高残差(未低下)` | 比較可能サンプルが基準以上、残差 `≥ +20%`、かつ傾き `≥ 0%` / Epoch |
| `高残差(要確認)` | `高残差(緩慢)` | 比較可能サンプルが基準以上、残差 `≥ +20%`、かつ傾きが `-2.0%`〜`0%` / Epoch |
| `高残差(低下中)` | `高残差(低下中)` | 比較可能サンプルが基準以上、残差 `≥ +20%`、かつ傾き `≤ -2.0%` / Epoch |
| `平均以下` | `平均以下` | 比較可能サンプルが基準以上、かつ残差 `≤ -20%` |
| — | `平均付近` | 比較可能サンプルが基準以上、かつ残差が `-20%`〜`+20%` の範囲内 |

### `loss.jsonl` の記録仕様

- **含まれる重み**：画像内の画素・トークンで平均したサンプル損失に、モデルのタイムステップ重み（`--weighting_scheme`、[タイムステップ](timesteps.ja-JP.md#weighting)参照）および masked loss 重み（有効時）が含まれます。
- **含まれない重み**：サンプル単位の `loss_weight`（正則化画像の `--prior_loss_weight` 等）およびその後に適用される重み付け（`--min_snr_gamma` 等）は記録された `loss` には含まれません。
- **保存間隔とマルチ GPU**：約 5 秒ごとに `status.json` と同時に書き出されます（プロセスが強制終了された場合は直前の数ステップが欠けることがあります）。マルチ GPU 環境では rank 0 が処理したサンプルのみが記録されます。
