# データセット診断

**SDXL**・**Anima**・**MOSS-Image** に対応しています（Krea 2 / `musubi-tuner` は `loss.jsonl` に未対応）。

学習の各ステップでは画像ごとにランダムなノイズタイムステップが抽選され、生の損失（Loss）はノイズ強度によって大きく変動します。たまたま損失の高いタイムステップが多く当たっただけで平均損失が高く見えることがあるため、生の損失で画像同士を直接比較することはできません。

本機能は Kohya `sd-scripts` のサンプル別分析の考え方（詳細は上流ドキュメント [`loss.jsonl` と残差分析](https://github.com/kohya-ss/sd-scripts/blob/v0.13.1/docs/run_control.md#analyzing-the-loss-log--loss-%E3%83%AD%E3%82%B0%E3%81%AE%E5%88%86%E6%9E%90) を参照）に基づき、各サンプルを**近いタイムステップ（ノイズ強度）**の中で比較し、2 つの指標で問題を特定します：

- **残差（相対的な難易度）**：同じタイムステップ区間の平均損失に対する各サンプル損失の相対差です。`0%` が全体平均で、正の値が大きいほど難しく、負の値が小さいほど易しいことを示します。
- **エポックあたりの傾き（収束しているか）**：比較可能なエポックが 3 回以上揃った後、同エポックの他画像に対する残差の変化速度を示します。負の値はモデルが吸収中であること、`0%` 付近または正の値は停滞を示します。

いずれも**同一学習ラン内**での相対比較です。モデル全体の収束品質はチェックポイントの生成プレビューと合わせて判断してください。

## 実際の見方：状態判定と対処の目安

上流の `analyze_run_loss.py` は残差順の並び替えのみを行いますが、本画面では**最小サンプル**（既定は比較可能サンプル `3` 回以上）・残差 `±20%`・**収束傾きしきい値**で画像を自動分類します。

収束傾きしきい値は短期学習（`6` エポック以下）では **`-2.0% / エポック`**、6 エポックを超える学習では**観測エポック幅での累計低下幅 `10%` 以上**に相当するよう自動換算（下限 **`-0.4% / エポック`**）され、長期学習で着実に下がっている画像が停滞と誤判定されるのを防ぎます。これらの数値は絞り込み用の目安であり、実際の確認では散布図の外れ値や一覧のソート順と併用してください：

| 状態サイン | 判定条件（上から順に判定） | 主な原因と推奨される対応 |
| --- | --- | --- |
| `NaN / Inf` | 非有限の損失を記録（最優先） | 個別画像はファイル破損や色空間異常を確認。多発時は学習率と混合精度を見直す |
| `集計待ち` | 有効サンプルまたは同区間の比較対象 `< 最小サンプル`（詳細は**サンプル不足 / 比較対象不足**） | サンプルが十分に蓄積されるまで待つか、上部の**最小サンプル**を一時的に下げて確認 |
| `高残差（要確認）` | 残差 `≥ +20%`、かつ 3 エポック未満または傾きが収束しきい値未達（詳細は**要確認 / 未低下 / 微減**） | 平均より高いまま下がらない状態。タグ漏れ・誤記・破損画像・不適切なトリミング・特徴の競合が多いため、詳細モーダルで元画像とキャプションを確認し、独立ファイルは**タグ編集で開く**から修正 |
| `高残差（低下中）` | 残差 `≥ +20%`、かつ傾き `≤ 収束傾きしきい値` | 構図や特徴は複雑だがモデルが順調に吸収中。画像を残して後続エポックを観察 |
| `平均より低い` | 残差 `≤ -20%` | 単純な構図や類似・重複画像。多数が極端に低い場合は生成プレビューで過学習を確認 |
| `平均付近` | `-20% < 残差 < +20%` | データセット全体と揃って進行しており、個別の対処は不要 |

## 確認手順と主な設定

1. **概要タブで「個別画像の問題」か「グループ全体の偏り」かを切り分ける**
   - **左欄の散布図**：3 エポック未満は残差の 1 次元分布、3 エポック到達後は横軸が残差・縦軸が傾きの 2 次元散布図になります。**右上領域**（高残差かつ収束しきい値未達）が優先確認対象の個別画像です。点をクリックするとプレビューカードを固定し、詳細モーダルを開けます。
   - **右欄のグループ比較**：**サブセット / フォルダ / バケットサイズ / バッチサイズ**ごとに平均残差と傾きを集計します。特定のサブセット・フォルダ・バケット全体が高い場合は、繰り返し回数（`num_repeats`）・タグ付け傾向・アスペクト比のトリミング差・サブセットのタイムステップオフセットを確認してください。行末の **`↗`** で該当グループの画像一覧へ移動できます。
   - **右欄のタイムステップ区間（`1000 → 0`）**：去噪順（左が高ノイズ、右が低ノイズ）に 18 区間の平均損失、高・中・低ノイズのサンプル割合、破線の理論分布を表示します。状態・グループ・個別画像にホバーまたは選択すると比較曲線が重なり、どのノイズ帯で偏っているかを確認できます。
2. **詳細モーダルで元画像・バケット切り抜き・キャプションを照合する**
   - 左側で `元画像 → バケット` の解像度とトリミング／拡大率を確認し、被写体の見切れや過度な引き伸ばしがないか見ます。
   - 右側でエポック別の残差推移、全画像平均に対する各タイムステップのサンプル位置、適用中のキャプションを確認します。
3. **ヘッダーの範囲切替と再開時の実行選択**
   - **データセット範囲**：正則化画像を含む場合、正則化画像が学習画像の平均基準を歪めないよう既定で**学習データのみ**になります。必要に応じて**正則化データのみ / すべてのデータセット**へ切り替えられます。
   - **実行（記録区間）**：同じ出力先と名前で再実行すると、同一の `loss.jsonl` に新しい記録が追記されます。**途中再開（Resume）**時はヘッダーの**実行**で**全実行を統合**を選び、**同名で最初から再学習**したときは既定の**最新**のままにします。

## 算出仕様と上流との違い

本トレーナーは `sd-scripts` の `--run_control` が書き出す `loss.jsonl` を読み取り、上流の [`tools/analyze_run_loss.py`](https://github.com/kohya-ss/sd-scripts/blob/v0.13.1/tools/analyze_run_loss.py) に対して以下の拡張を行っています：

- **残差の基準（10 区間）**：観測されたタイムステップ範囲を 10 等分し、同じ区間に **2 枚以上の異なる画像**がある場合のみ比較対象とします（タイムステップ欠損や単独サンプルは平均損失と総サンプル数にのみ計上）：

<div class="doc-equation" role="group" aria-label="サンプル残差の計算式">
  <div class="doc-equation-kicker">サンプルの残差</div>
  <div class="doc-equation-expression">残差 = サンプル損失 ÷ 同タイムステップ区間の平均損失 − 1</div>
  <p>画像・グループの残差は比較可能なサンプル残差の平均値です（<code>0%</code> が平均、正は難しい、負は易しい）。</p>
</div>

<!-- doc-anchor: slope -->
- **同エポック・同区間基準の傾き**：全体の損失低下による影響を除外するため、**同じエポック・同じタイムステップ区間の他画像の平均損失**（`> 0`）を基準に各エポックの残差を求め、3 エポック以上揃った時点で最小二乗法により傾きを算出します。
- **タイムステップ重みの復元**：`loss.jsonl` の `loss` には `--weighting_scheme`（[タイムステップ](timesteps.ja-JP.md#weighting)参照）と masked loss 重みが含まれ、サンプル `loss_weight`（`--prior_loss_weight` 等）や `--min_snr_gamma` は含まれません。**Anima** と **MOSS-Image** で `sigma_sqrt` または `cosmap` を使用している場合、集計前にタイムステップ重みを除して未重み付け損失へ復元してから残差を計算します。
- **書出間隔とマルチ GPU**：約 5 秒ごとに `status.json` とあわせて書き出され、マルチ GPU 学習ではメインプロセス（rank 0）のサンプルのみ記録されます。各フィールドの詳細は Kohya 上流ドキュメント [`run_control.md#lossjsonl`](https://github.com/kohya-ss/sd-scripts/blob/v0.13.1/docs/run_control.md#lossjsonl) を参照してください。
