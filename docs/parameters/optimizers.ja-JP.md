# オプティマイザの選び方と設定

<!-- doc-anchor: quick-choice -->
## オプティマイザを選ぶ

オプティマイザは、勾配を使ってモデルのパラメータを更新します。主に学習速度、メモリ使用量、安定性に影響します。

最初は AdamW8bit を使ってください。更新が急増する場合は StableAdamW、オプティマイザの状態が VRAM に収まらない場合は Paged 版と比較します。切り替えたら、下の学習率表で開始値を確認してください。

| 目的 | 比較候補 | 確認する点 |
| --- | --- | --- |
| 基準を作る | AdamW8bit | 学習率、学習時間、データの問題を切り分けやすいか |
| 状態のメモリを減らす | 8-bit 版、必要なら Paged 版 | ピークメモリと転送の負荷 |
| 更新の急増や低精度の丸めに対応する | StableAdamW | 最後の画像だけでなく、異常な更新が減るか |
| 状態の因子分解と更新クリッピングを試す | CAME | 安定性、速度、生成結果 |
| 更新幅の手動調整を減らす | Prodigy 系 | 自動推定が適切な範囲に速やかに到達するか |
| 行列の更新方式を比較する | Muon、SOAP | 学習速度と追加の計算負荷 |
| LoRA の因子に合わせた方式を試す | LoRA-Muon、LoRA-RITE | 因子ペアへの対応と、個別に調整した学習率 |

<!-- doc-anchor: optimizer-type -->
## 使用できるオプティマイザ

| オプティマイザ | 主な用途 | 制約・注意点 |
| --- | --- | --- |
| AdamW | 全精度の AdamW 基準 | 8-bit 版より状態の VRAM 使用量が多い |
| AdamW8bit | 通常の既定値 | 小さなテンソルは仕様上、状態を FP32 で保持する |
| PagedAdamW8bit | 通常の 8-bit 版でも VRAM が不足する場合 | 違いはページングのみ。CPU–GPU 転送で遅くなる場合がある |
| StableAdamW | 勾配の急増、低精度の LoRA 重み | AdamW8bit より状態メモリが多い。過学習を防ぐものではない |
| Lion | 勾配の符号とモメンタムを使う方式の比較 | 学習率の範囲が異なるため、個別に調整する |
| Lion8bit | Lion の状態メモリを減らす | 独自の学習率比較が必要 |
| PagedLion8bit | Lion8bit でもページングが必要な場合 | ページングは画質を改善せず、遅くなる場合がある |
| Prodigy | 更新幅の自動推定 | 基本学習率は `1.0`。本ツールでは LoRA+ 非対応 |
| ProdigyPlusScheduleFree | 更新幅の自動推定と内部スケジュール | 外部スケジューラとウォームアップは無効。基準となる結果と比較する |
| Automagic3 | 実験的な適応方式 | 基準を作ってから比較。勾配累積は 1 のみ。fp16 混合精度と複数 GPU は非対応 |
| AdaFactor | 状態メモリを極力抑える | 相対ステップモードが学習率を管理し、LoRA+ に制約がある |
| CAME | 異なる出典の画像や更新幅のばらつきを比較する | 3 つの beta と内部 RMS クリッピングを使う |
| AdamWScheduleFree | 外部スケジューラなしの AdamW を試す | 内部ウォームアップに対応するが、本ツールの既定値は `warmup_steps=0`。短い学習の第一候補にはしない |
| EmoSens | 実験的な方式 | 勾配累積は 1 のみ。fp16 混合精度、複数 GPU、LoRA+ は非対応 |
| Muon | 2 次元 LoRA 行列のモメンタムを直交化する | Anima LoRA のみ。PyTorch の実装を使う。同じ条件で AdamW8bit と比較する |
| LoRA-Muon | 標準 LoRA の因子ペアに合わせた低ランクのスペクトル最適化 | `anima-lora` と `networks.lora_anima` のみ。LoRA+、LyCORIS の LoKr・LoHa などは非対応。独自の学習率調整が必要 |
| Adan | 勾配間の変化も使う更新 | 本ツールの開始学習率は AdamW の半分。3 つの beta を使う |
| AdEMAMix | 長い学習や、勾配のノイズが目立つ場合の比較 | 短い学習では遅い移動平均の利点が不確か。alpha と立ち上げ期間を学習時間に合わせる |
| AdEMAMix8bit | AdEMAMix の状態メモリを減らす | 全精度版との主な違いは状態の量子化 |
| LoRA-RITE | LoRA の構造に合わせた更新を試す | Anima の標準 LoRA のみ。LoRA+ 非対応。内部クリッピングを使い、`max_grad_norm`（全体の勾配クリッピングしきい値）は 0 に固定 |
| SOAP | 回転した座標系で Adam 型の更新を行う | 前処理のメモリと計算が増える。本ツールの前処理次元の上限は既定で `256` |

上のメモリ比較は、オプティマイザの状態だけについての説明です。ピーク使用量には解像度、rank、バッチサイズ、キャッシュ、生成プレビューも影響します。

<!-- doc-anchor: stable-comparison -->
## AdamW8bit・CAME・StableAdamW の違い

**AdamW8bit は比較の基準です。** 状態メモリが少なく、動作が広く知られており、学習率、ステップ数、データの問題を切り分けやすくなります。具体的な安定性やメモリの問題がなければ、これを使ってください。

**CAME は因子分解した状態と内部 RMS クリッピングを使います。** 状態の保存方法や更新の安定化を比較できます。出典の異なるデータは、先に画像を整理し、キャプションを整えてください。

**StableAdamW は異常に大きな更新を抑えます。** 通常のスケジューラ、ウォームアップ、`max_grad_norm`、LoRA+ に対応します。Anima の開始値は `lr=2e-5`、`betas=(0.9, 0.99)`、`eps=1e-8`、`weight_decay=0`、SDXL の学習率は `1e-4` です。状態メモリは AdamW8bit より多く、主に更新の不安定さへの対策として使います。

## パラメータ一覧

<!-- doc-anchor: learning-rate -->
### 学習率

学習率は更新量を決めます。高いと学習が速くなりますが、損失の急増、構図の固定化、プロンプトへの追従低下が起きやすくなります。低いと更新が小さくなり、より多くのステップが必要です。

下の表は本ツールの開始値です。更新の尺度は方式ごとに異なるため、個別の調整が必要です。データセットごとの最適値ではありません。

| オプティマイザ | Anima の開始学習率 | 意味 |
| --- | ---: | --- |
| AdamW / AdamW8bit / PagedAdamW8bit | `2e-5` | Anima 公式の rank 32 の基準。8-bit・Paged 版も同じ学習率の意味を持つ |
| StableAdamW | `2e-5` | まず AdamW と揃え、更新安定化の違いを確認する |
| Muon (`match_rms_adamw`) | `2e-5` | 行列サイズに応じて更新 RMS を AdamW の範囲に合わせる |
| LoRA-Muon | `0.02` | 実験的な開始値。個別に調整する。コンストラクタの既定値は `0.1` |
| CAME | `1.5e-5` | AdamW の `0.75` 倍から開始 |
| Adan | `1e-5` | AdamW の `0.5` 倍から開始し、収束を比較する |
| AdEMAMix / AdEMAMix8bit | `2e-5` | 論文は Adam と同程度の学習率を使う。8-bit 版も同じ意味 |
| LoRA-RITE | `1e-4` | Adam と尺度が異なるため、個別に調整する |
| SOAP | `2e-5` | AdamW の基準から比較する |
| Lion / Lion8bit / PagedLion8bit | `5e-6` | 論文の目安は AdamW の約 `1/3`〜`1/10` |
| AdamWScheduleFree | `1e-4` | Schedule-Free の目安は元の方式の `1`〜`10` 倍。Anima では実験的な値 |
| Prodigy / ProdigyPlus | `1.0` | D 適応の倍率で、`2e-5` とは直接比較できない |
| AdaFactor 相対ステップ | オプティマイザが管理 | 相対ステップを無効にした Anima の手動設定は `2e-5` から開始 |
| Automagic3 / EmoSens | `1e-4` / `0.1` | 内部で変動する学習率の基準値。通常の固定学習率とは異なる |

Lion の `5e-6` は、論文の「AdamW の約 1/3〜1/10」という目安を使った値です。論文では重み減衰も約 3〜10 倍にすることを推奨していますが、本ツールは採用していません。公式の設定一式ではありません。

SDXL は別の基準を使います。AdamW／StableAdamW と CAME は `1e-4`、Lion は `2e-5`、AdamWScheduleFree は `3e-4` です。モデル種別やオプティマイザを変えたとき、UI が置き換えるのは未編集の推奨値だけです。読み込んだ設定や手動の値は維持します。

`network_alpha / network_dim` は LoRA 枝の倍率です。上流 sd-scripts の `1e-4` の例は実質 `alpha=1` を想定し、alpha を上げる際は学習率を下げるか再検証するよう明記しています。本ツールの既定値 `rank=32, alpha=32` にそのまま適用しないでください。

早い段階でキャラクターが固定化し、色が混ざり、プロンプトへの追従が低下する場合は、学習率かステップ数を下げます。学習不足なら、トリガーワードと有効なステップ数を確認してから少し上げます。Lion は AdamW と使える範囲が異なるため、独立して試してください。

<!-- doc-anchor: scheduler-warmup -->
### 学習率スケジューラとウォームアップ

AdamW、AdamW8bit、StableAdamW、Lion、CAME、Muon、LoRA-Muon は外部スケジューラを使います。新しい Anima 設定の既定値は、上流の例に合わせた `constant` です。短い学習の変数を減らせます。`cosine_with_restarts` は既定の `num_cycles=1` では再スタートせず、1 より大きい場合に再スタートします。既存の手動設定も使えます。ウォームアップを試す場合は `constant_with_warmup` を使い、最初は総更新ステップ数の `5%` 未満にしてください。

AdamWScheduleFree と ProdigyPlus は内部でスケジュールを管理するため、UI は外部スケジューラを constant に固定します。AdamWScheduleFree の内部ウォームアップは `lr_warmup_steps` と別です。ProdigyPlusScheduleFree には同等の設定項目がありません。

スケジュール項目の **学習率の曲線を表示** を開くと、ウォームアップ、減衰、再スタートを確認できます。サイドバーには選択中の学習対象の実効学習率とウォームアップステップ数が表示されます。DiT とテキストエンコーダの両方を学習する場合は、対象を切り替えて確認してください。総ステップ数が未確定なら推定の注記も確認します。曲線が示すのはスケジューラの出力で、オプティマイザ内部の適応的な更新量ではありません。

![ComfyUI テーマの学習率曲線：10,000 ステップ、ウォームアップ 500 ステップ、cosine 減衰](../images/lr-preview.ja-JP.jpg)

| 設定 | 主な目的 | 過度に調整した場合 |
| --- | --- | --- |
| モメンタム関連の係数 | 短期の変動を抑え、最近または長期の傾向を使う | 履歴を長く残しすぎると適応が遅れる |
| 重み減衰 | 学習する重みの増加を抑える | 強すぎると必要な特徴を学習できない |
| 勾配クリッピング | 一時的に大きな勾配を抑える | しきい値が低すぎると通常の更新も抑える |
| 数値安定性の項目 | 小さすぎる分母による増幅を防ぐ | 大きい値は適応的な倍率そのものを変える |

安定している場合は既定値を使い、先に学習率と学習時間を調整してください。

<!-- doc-anchor: betas -->
### モメンタム係数（betas）

変更する理由がなければ、既定値を使ってください。

- AdamW 系：`0.9, 0.999`
- StableAdamW、Lion：`0.9, 0.99`
- CAME：`0.9, 0.999, 0.9999`

大きい値は履歴を長く残し、反応が遅くなります。小さい値は最近の勾配を重視します。各 beta が制御する統計は方式ごとに異なるため、個別の説明も確認してください。

<!-- doc-anchor: eps -->
### 数値安定化項（eps）

`eps` は小さすぎる分母による更新の増幅を防ぎます。StableAdamW は `1e-8`、PyTorch Muon は `1e-7` が既定値です。再現する数値エラーを調べる場合を除き、変更しないでください。

<!-- doc-anchor: weight-decay -->
### 重み減衰

本ツールの開始値は、AdamW、AdamW8bit、PagedAdamW8bit が `weight_decay=0.01`、CAME、StableAdamW、Muon、LoRA-Muon が `weight_decay=0` です。PyTorch Muon 自体の既定値は `0.1` ですが、本ツールは LoRA の開始値として `0` を明示的に渡します。UI で編集できます。

大きい値は重みを強く縮め、必要な特徴の学習を妨げる場合があります。小さい値は制約を弱め、`0` は無効にします。キャラクター LoRA は本ツールの既定値から始め、正則化の強さを比較する場合に減衰だけを変えてください。

<!-- doc-anchor: muon-options -->
### Muon の設定

Muon は勾配のモメンタムを蓄積し、2 次元行列の更新を近似的に直交化します。`lora_down` と `lora_up` を別々に処理します。行列に基づく更新が学習速度と結果に与える影響を比較できます。

全精度 AdamW がパラメータごとに 2 つの状態を持つのに対し、Muon はモメンタム状態を 1 つ持ちます。ただし、各ステップで行列積が増えます。ピーク VRAM と 1 ステップの時間も記録してください。

#### 更新の大きさ

- **学習率**（`learning_rate`、Anima の既定値 `2e-5`）：更新量を直接制御します。高すぎると過学習、損失のばらつき、不安定な更新が起きやすく、低すぎると学習が遅くなります。既定の倍率では AdamW の基準を比較の開始値にできます。
- **学習率の補正**（`adjust_lr_fn`、既定値 `match_rms_adamw`）：行列サイズで更新を補正します。変更したら学習率を再調整してください。
- **重み減衰**（`weight_decay`、既定値 `0`）：大きいほど LoRA 因子を縮めます。過学習が減る場合も、キャラクターの学習が弱まる場合もあります。PyTorch の既定値は `0.1` ですが、本ツールは UI の値を渡します。

#### モメンタム

- **係数**（`momentum`、既定値 `0.95`）：高いと滑らかになりますが新しい勾配への反応が遅くなり、低いと現在のバッチを重視します。
- **Nesterov モメンタム**（`nesterov`、既定で有効）：直交化前の勾配と履歴の組み合わせ方を変えます。無効化は計算速度だけでなく、最適化の経路も変えます。

#### 直交化

- **反復回数**（`ns_steps`、既定値 `5`）：増やすと計算量が増えます。この近似は、無制限に反復して厳密な直交化へ収束させる設計ではありません。通常は `5` を使い、計算負荷の比較時に調整してください。
- **反復係数**（`ns_coefficients`、既定値 `3.4445, -4.775, 2.0315`）：Newton–Schulz 反復の多項式を定めます。変更で近似精度の低下や数値問題が起きるため、条件を揃えた実験向けです。
- **数値安定化項**（`eps`、既定値 `1e-7`）：正規化時の小さすぎる値による除算を防ぎます。通常への影響は小さく、再現する NaN や異常な増幅を調べる際に確認します。

最初の比較では、データ、rank、alpha、スケジューラ、ステップ数、学習率を揃え、AdamW8bit だけを Muon に変えます。安定したら学習率か重み減衰を 1 つずつ試してください。NS 係数と反復回数も同時に変えないでください。

<!-- doc-anchor: lora-muon-options -->
### LoRA-Muon の設定

LoRA は 2 つの因子の積として作用します。一方を大きくし、もう一方を同じ比率で小さくしても積は変わりません。通常の Muon は因子を個別に更新するため、この尺度の配分に影響されます。

LoRA-Muon は因子をペアで処理し、両者が表す重みの変化を更新することを目指します。通常の Muon の切り替え項目ではなく、独自の学習率調整が必要です。

#### パラメータ一覧

| パラメータ | 渡し方 | 既定値 | 許容値 | 効果と使い方 |
| --- | --- | ---: | --- | --- |
| `learning_rate` | 学習設定の項目。コンストラクタには `lr` として渡す | Anima の自動推奨値 `0.02`、コンストラクタ `0.1` | 有限値 `≥ 0` | 全体の更新量。最初に調整する。AdamW の値をそのまま使わない |
| `weight_decay` | UI 共通項目。最終的にオプティマイザ引数として渡す | `0` | 有限値 `≥ 0`、かつ `learning_rate * weight_decay < 1` | 論文の分割した分離型減衰。比較で効果を確認するまでは `0` |
| `momentum` | `optimizer_args` | `0.9` | `0 ≤ momentum < 1` | 勾配の指数移動平均。高いほど滑らかだが反応が遅い |
| `ns_steps` | `optimizer_args` | `8` | 整数 `1–8` | Polar Express / Newton–Schulz の行列符号反復。減らすと計算が軽くなり、近似が粗くなる |
| `inv_sqrt_steps` | `optimizer_args` | `7` | 整数 `1–7` | 通常の Gram 行列の逆平方根計算の反復回数。初期状態の保護と固有値分解による代替経路では使わない。通常は既定値 |
| `msign_eps` | `optimizer_args` | `1e-20` | 有限値 `≥ 0` | 行列符号の正規化でゼロ除算を防ぐ |
| `inv_sqrt_eps` | `optimizer_args` | `1e-5` | 有限値 `≥ 0` | Gram 行列の正則化、初期状態のしきい値、固有値の下限。更新に作用するため、通常は既定値 |
| `inv_sqrt_gamma` | `optimizer_args` | `1.001` | 有限値 `> 0` | 逆平方根反復の減衰。数値問題を調べる場合を除き、変更しない |
| `gauge_rebalance` | `optimizer_args` | `false` | `true` / `false` | 因子の大きさを定期的に揃える。数値条件の改善であり、過学習を抑える正則化ではない |
| `gauge_rebalance_alpha` | `optimizer_args` | `1.0` | `0 < alpha ≤ 1` | 再調整の減衰指数。`1` に近いほど強く調整する。有効化時のみ作用 |
| `gauge_rebalance_interval` | `optimizer_args` | `1` | 整数 `≥ 1` | 再調整の間隔（更新ステップ数） |
| `gauge_power_steps` | `optimizer_args` | `2` | 整数 `≥ 1` | 因子のスペクトルノルムを推定するべき乗反復回数 |
| `max_grad_norm` | 学習コードの項目。LoRA-Muon のコンストラクタ引数ではない | Anima の自動推奨値 `0` | `≥ 0` | `optimizer.step` 前の全体の L2 勾配クリッピング。`0` で無効。論文の方式には含まれない |

最初は主に `learning_rate` を調整します。`momentum=0.9`、`ns_steps=8`、`inv_sqrt_steps=7` と数値保護は既定値を使い、因子の尺度調整を試す目的がなければ `gauge_rebalance` は無効にしてください。

`0.02` から始め、データ、rank、alpha、スケジュール、ステップ数を固定して、倍率で増減した値を比較します。短い学習で学習不足と損失の急増を確認し、範囲を絞ります。

Anima の本体 LoRA では、`unet_lr` が入力されていると、そのグループは `learning_rate` より優先して使います。`reg_lrs` に一致するモジュールも独自の値を使います。全体の学習率変更が対象に届くか、先に確認してください。

#### ネットワーク設定と互換性

`network_dim` と `network_alpha` はネットワーク側の設定で、コンストラクタ引数ではありません。同じ値にする必要もありません。

- `network_dim` は LoRA の rank です。
- `network_alpha / network_dim` は順伝播での LoRA 枝の倍率です。
- オプティマイザはこの倍率を明示的に補正しません。rank の比較では `alpha / dim` を揃え、比率を変えたら学習率を再調整してください。
- `alpha=dim` は倍率を `1` にするだけで、LoRA-Muon の必須条件ではありません。
- 各モジュールには、rank 次元が一致する完全な `lora_down` と `lora_up` のペアが必要です。

パラメータ数、モメンタム状態、Gram 行列の計算を減らすには、手動で `dim=16, alpha=16` から試せます。LoRA-Muon の選択だけでは rank と alpha は自動変更されません。

現在の対応範囲：

- `model_train_type=anima-lora` と `network_module=networks.lora_anima` の組み合わせのみ。
- LoRA+ は非対応。グループ分割で完全な `lora_down → lora_up` のペアが崩れるためです。
- LyCORIS の LoKr、LoHa、DoRA などは非対応。
- Linear LoRA と Anima が使う Conv LoRA の形状に対応。
- FP16／BF16 パラメータの行列演算は FP32 で行い、元の型へ書き戻します。別の `dtype` 設定は不要です。
- 一次モーメントは FP32 を保ちます。状態の復元時はチェックポイントから計算用の型と現在のデバイスへ直接移し、中間の FP16／BF16 変換を避けます。
- sd-scripts の通常の学習率スケジューラに対応。スケジューラとウォームアップを内部管理しません。

#### 計算で使う用語

| 用語 | この方式での意味 |
| --- | --- |
| 因子のペア処理 | 同じ LoRA の down 行列と up 行列を一緒に処理する |
| Gram 行列 | 因子内の方向の大きさと相関を表す |
| ホワイトニング | 相手側の因子の統計を使い、現在の更新の方向ごとの尺度を調整する |
| 行列符号の方向 | 行列の方向を保ち、特異値の尺度を整える。要素ごとの符号ではない |
| 因子の再調整 | 等価な因子の大きさが極端に違わないよう、数値条件を整える |

#### 1 回の更新

1. 各因子の勾配の指数移動平均を計算します。
2. 相手側の Gram 行列の逆平方根を使い、現在の因子の方向別の尺度を調整します（ホワイトニング）。
3. 調整したモメンタムに行列符号演算を適用し、更新に必要な 2 つ目の Gram 逆平方根を掛けます。
4. 学習率 `η` を合成した重みの一次の更新幅として扱い、2 つの因子の方向に等分します。

論文では `η` を信頼領域の半径と呼びます。制限するのは、合成した重みの一次更新のスペクトルノルムです。down／up の各要素の変化量の上限ではありません。

<!-- doc-anchor: adan-options -->
### Adan の設定

Adan は勾配と、連続する勾配間の変化を追跡します。Anima は `1e-5` から始め、学習速度、損失の安定性、最良のチェックポイントで調整します。

- **Betas**（`0.98, 0.92, 0.99`）：順に勾配平均、勾配差の平均、二乗勾配の統計を制御します。
- **Epsilon**（`1e-8`）：AdamW と同じ意味です。
- **重み減衰**（`weight_decay=0.01`）と **分離型減衰**（`weight_decouple`、既定で有効）：有効時は更新前に `1 − lr × weight_decay` を掛け、無効時は更新後に `1 + lr × weight_decay` で割ります。通常は既定値を使います。
- Adan 内部の `max_grad_norm` 引数は `0` です。クリッピングは UI の全体の勾配クリッピングしきい値（`max_grad_norm`）で行います。

<!-- doc-anchor: ademamix-options -->
### AdEMAMix の設定

短期と長期の勾配傾向を使います。短期は素早く反応し、長期は一時的な変動を抑えますが、不要になった初期の方向も残す場合があります。

| パラメータ | 役割 | 大きくした場合 |
| --- | --- | --- |
| `alpha` | 長期傾向の重み | 記憶期間を変えず、その影響を強める |
| 3 つ目の beta | 長期履歴の保持 | 1 に近いほど長く保持し、反応が遅くなる |
| `t_alpha` | 長期の重みを立ち上げる期間 | 目標の重みに届くのが遅くなる |
| `t_beta3` | 履歴保持係数を変える期間 | 目標の記憶期間に届くのが遅くなる |

この `alpha` は混合の重みで、ネットワークの Alpha とは別です。短い学習もまず既定値で始め、長期傾向が作用するのが遅すぎる場合に立ち上げ期間を短くします。

`alpha` の既定値は `5.0`、`0` は遅い平均を更新から除きます。`t_alpha` と `t_beta3` は既定で空欄です。カスタム引数に指定がなければ、開始時の推定総ステップ数を使います。`0` は立ち上げなし、正の整数は立ち上げ期間です。alpha は 0、β3 は β1 から始まります。

- **Betas**（`0.9, 0.999, 0.9999`）：短期勾配平均、二乗勾配平均、長期勾配平均。**Epsilon** は `1e-8`、**重み減衰**は `0.01` で、学習率に応じて適用します。
- 8-bit 版は 3 状態を量子化し、全精度の約 1/4 のメモリを使います。4,096 要素未満のテンソルを量子化しないのは仕様です。

<!-- doc-anchor: lorarite-options -->
### LoRA-RITE の設定

因子の尺度を除いた勾配と低ランク行列の前処理により、等価な A/B 表現への依存を減らします。Anima は `1e-4` から始め、AdamW8bit と比較します。

- **学習率**（`1e-4`）：まず `5e-5`〜`2e-4` で比較します。高いほど速く学習しますが、高すぎると損失が急増します。
- **Betas**（`0.9, 0.999`）：通常の 2 つの係数です。
- **Epsilon**（`1e-6`）：内部で二乗して使う「平方根側の epsilon」です。Adam 型の `1e-8` を流用しないでください。
- **勾配クリッピングしきい値**（`clip_unmagnified_grad=1.0`）：一時的な勾配の急増を抑えます。通常は既定値で十分です。LoRA 因子による倍率を除いた後のノルムを測ります。UI の全体のしきい値は `0` に固定され、この項目が代わりに使われます。`0` で無効です。
- Anima の標準 LoRA のみ。LyCORIS の LoHa、LoKr、DoRA などは非対応。グループ別学習率がペアの前提を崩すため、LoRA+ も非対応です。
- 通常の up 行列のゼロ初期化では、最初は主に up が更新され、数ステップ後に down も更新されます。正常な動作です。

<!-- doc-anchor: soap-options -->
### SOAP の設定

勾配方向の相関から座標系を選び、その中で Adam 型の更新を行って元へ戻します。要素ごとの倍率だけでなく、行列の方向間の関係も使います。

| パラメータ | 既定値 | 効果と調整 |
| --- | --- | --- |
| `max_precondition_dim` | `256` | 前処理する軸の上限。上げるとメモリと計算が増え、下げると要素ごとの倍率だけを使う軸が増える |
| `precondition_frequency` | `10` | 座標系を更新する間隔。大きいと軽く、小さいと変化を早く追う。`1` は毎ステップ |
| `shampoo_beta` | 空欄（2 つ目の beta を使う） | 大きいと履歴を長く保持し、反応が遅くなる |
| `normalize_gradient` | 無効 | 更新テンソル全体を RMS で正規化する |
| `correct_bias` | 有効 | ゼロから始まる平均の偏りを補正する |
| `precondition_1d` | 無効 | `train_norm` で学習する正規化層の重みなど、上限内の 1 次元パラメータも前処理する |

- **学習率**（Anima `2e-5`）：AdamW の基準から始めます。ライブラリの `3e-3` はモデル全体の学習向けで、流用しないでください。
- **Betas**（`0.95, 0.95`）：別に指定しなければ、2 つ目は前処理の移動平均にも使います。AdamW の `0.9, 0.999` との比較は、二次モーメントの記憶期間も変わります。
- **Epsilon**（`1e-8`）：二乗勾配状態の平方根の後に加えます。AdamW と同じ意味です。
- **重み減衰**（`0`）：ライブラリの `0.01` を上書きし、設定へ明示的に書きます。常に学習率に応じた分離型減衰を使い、切り替え項目はありません。
- **勾配クリッピング**：内部にはありません。全体の `max_grad_norm` が通常どおり使えます。既定の `1.0` は sd-scripts と同じで、設定には書き出しません。固定される項目もありません。
- 統計と座標系の行列は軸長の二乗に比例するメモリを使います。FP32 の 2 行列は 512 次元で約 2 MiB、1,024 次元で約 8 MiB です。Anima の 2,048・8,192 次元の大きな行列を避けるため、通常は上限 `256` を使います。
- 最初の更新は前処理の状態を作るだけで、重みを変えません。2 ステップ目から実際の更新が始まるのは、この実装の正常な動作です。

<!-- doc-anchor: prodigyplus-options -->
### ProdigyPlus の設定

Prodigy 系は学習中に更新幅を推定し、学習率欄は主にその倍率として働きます。表示の `1.0` は AdamW の学習率 `1.0` とは意味が異なります。

| 値 | 意味 | 既定値と使い方 |
| --- | --- | --- |
| `D` | 更新幅の推定尺度 | 学習中に更新。ログで確認する |
| 学習率欄 | 更新幅の計算に使う倍率 | `1.0` を維持する |
| `d0` | 初期推定値 | `1e-6`。通常は変更しない |
| `d_coef` | 推定に掛ける倍率 | `1.0`。自動更新幅を調整する際に先に試す。大きいと推定値が上がる |

ProdigyPlusScheduleFree は評価・保存用の平均重みも保持します。最後の状態だけに依存しにくくなりますが、新しく学習した変化が保存結果へ反映されるまで時間が掛かる場合があります。

`schedulefree_c=0` は元の平均化規則を使います。正の値同士では、大きいほど最近の更新を早く反映し、小さいほど滑らかになります。`0` は別の規則を選ぶ値で、その範囲の下端ではありません。

ログのグループ学習率、`D × lr`、実際のパラメータ更新量は別の指標です。曲線が何を記録するかを確認し、複数段階の生成画像で評価してください。

- **D の増加制限**（`d_limiter`、既定で有効）：`d_coef=1` では 1 ステップの増加を約 19% に制限します。増加が遅い場合は無効と比較できますが、一時的な過大推定を受けやすくなります。SPEED は独自の制限を使い、この設定を読みません。
- **D を固定するまでのステップ数**（`prodigy_steps=0`）：指定回数後に D を固定し、推定バッファを解放します。D が妥当と確認でき、後半は変えたくない場合に使います。`0` は最後まで推定します。
- **バイアス補正と自動ウォームアップ**（`use_bias_correction`、既定で無効）：RAdam 型を選び、D の調整が遅くなります。有効化後に D が増えなくなったら、無効と比較してください。
- **SPEED 推定**（`use_speed`、既定で無効）：方向に沿った進行が過去の最大値を超えたときだけ D を増やします。状態が少なく、勾配全体の倍率変化に対応します。実験的な機能で、重み減衰との併用時は安定性を確認してください。
- **Cautious 更新**（`use_cautious`、既定で無効）：現在の勾配と向きが異なる更新成分を除きます。この実装は一次モーメントを持たず、更新を直接マスクします。方向の選別を独立して比較する場合に使います。
- **直交勾配更新**（`use_orthograd`、既定で無効）：現在の重み方向に直交する勾配成分だけを使います。この制約を試す場合に有効化します。
- **グループ別の D 推定**（`split_groups`、既定で有効）：テキストエンコーダと DiT で別々に推定します。無効では共通の値を使います。通常は既定値です。
- **平均 D の共有**（`split_groups_mean`、既定で無効）：`split_groups` が必要です。推定値の調和平均に各グループの学習率を掛けます。小さい推定値が平均を引き下げます。無効なら各グループが独自の D を使います。
- **二次モーメントの因子分解**（`factored`、既定で有効）：行と列の統計で近似し、メモリを減らします。NaN や D の停滞を調べる際は、無効にして完全な統計と比較します。
- **因子分解した統計を FP32 で保持**（`factored_fp32`、既定で有効）：半精度の誤差を減らします。無効化でメモリが減るのは勾配も半精度の場合だけです。通常は有効にします。
- **学習率に応じた重み減衰**（`weight_decay_by_lr`、既定で有効）：適応学習率に合わせて減衰します。無効では毎ステップそのまま減衰し、初期の重みを縮めすぎる場合があります。通常は有効にします。
- **内部更新の補正**（`use_stableadamw`、UI では `prodigyplus_use_stableadamw`、既定で有効）：RMS で更新を制限します。この機能または Adam-atan2 の `eps=None` は、全体の勾配クリッピングを `0` に固定します。適応更新幅の異常を調べる際は無効と比較します。
- **詳細設定**（カスタム `optimizer_args`）：`use_grams` と `use_adopt` は実験的な更新方式です。`use_focus` は大きい更新幅のノイズに対応し、`factored` と Adam-atan2 を無効にします。`beta3` は D 推定用の移動平均を制御し、既定値は √β2 です。`stochastic_rounding` は BF16 重みだけに作用します。

<!-- doc-anchor: gradient-clipping -->
### 全体の勾配クリッピング（max_grad_norm）

通常の開始値は `max_grad_norm=1`、`0` は無効です。正の値が小さいほど強く抑え、大きいほど大きな勾配を許容します。StableAdamW に対応します。LoRA-Muon は `0` を推奨し、LoRA-RITE は `0` に固定して内部クリッピングを使います。

`percentile_clipping=95` と小さい `max_grad_norm` を併用すると、同じ更新を二重に抑える場合があります。ログで必要性を確認できなければ、弱いクリッピングを 1 つだけ使ってください。

<!-- doc-anchor: percentile-clipping -->
### パーセンタイルクリッピング

AdamW8bit、PagedAdamW8bit、Lion8bit、PagedLion8bit のみで有効です。

- `100`：無効。既定値。
- `99`：弱いクリッピングの比較用。
- `95`：強めの比較用。実際に勾配の外れ値があると確認してから使います。

低いほど強く抑えます。勾配の急増が繰り返される場合は `99` を試してください。強く抑えすぎると、少数の衣装や表情から得られる有用な更新も弱まります。

<!-- doc-anchor: min-8bit-size -->
### 8-bit 化する最小テンソルサイズ（min_8bit_size）

既定値は `4096`。これより小さいテンソルの状態は FP32 です。

上げると FP32 の状態と VRAM 使用量が増え、下げると量子化するテンソルが増えます。低ランク学習で小さいテンソルの数値問題を調べる場合は `16384` と比較してください。モデルのパラメータ精度を変える設定ではありません。

<!-- doc-anchor: stableadamw-options -->
### StableAdamW 専用設定

`kahan_sum=True` は補償付き加算で丸め誤差を減らします。主に LoRA の学習する重み自体が FP16／BF16 の場合に作用します。本ツールは `mixed_precision=bf16` でも LoRA 重みを FP32 に保ち、`full_bf16` の場合だけ変換します。`full_bf16` がなければ、通常は効果が小さくなります。

`weight_decouple=True` は AdamW 型の分離型減衰を使います。`weight_decay=0` では作用しませんが、後から減衰を上げた場合に備えて有効のままにしてください。

<!-- doc-anchor: came-clipping -->
### CAME の内部クリッピング

`came_clip_threshold` の既定値は `1.0` で、`clip_threshold` として渡されます。内部更新の RMS を抑え、低いほど強く、高いほど弱く制限します。全体の `max_grad_norm` とは別です。更新の急増が繰り返される場合に調整してください。

<!-- doc-anchor: schedulefree-warmup -->
### Schedule-Free のウォームアップ

AdamWScheduleFree は内部の `warmup_steps` を使い、外部の `lr_warmup_steps` は無効です。本ツールの既定値 `0` はウォームアップなしです。初期の更新が不安定なら短い内部ウォームアップを試してください。大きいほど学習率の立ち上げが長くなります。

<!-- doc-anchor: stochastic-rounding -->
### 確率的丸め

低精度の更新が同じ方向に丸められ続けることによる偏りを減らします。ProdigyPlus はライブラリの既定値を使い、本ツールに独立した切り替え項目はありません。データ拡張ではなく、数値計算の処理です。

### EmoSens v3.9.3

EmoSens は損失の変化に応じて学習率を自動調整します。`learning_rate` には倍率を指定し、Anima LoRA は `0.1`、SDXL LoRA は `1.0` から始めます。実際の学習率は変動し、学習ログで確認できます。

**主な設定**

- **終了の目安となるしきい値** `stopcoef`：既定値は `0.04`。学習が落ち着き、最近の平均損失がこの値以下になると終了の検討を促します。大きいほど通知されやすくなります。`1` より大きい値も使え、`0` は通知条件を無効にします。
- **収束の通知** `notify`：既定で有効。ログの `[READY TO STOP]` は終了の目安で、自動終了しません。前後の保存モデルを比較して判断してください。無効化は表示だけに作用し、学習は変えません。
- **シャドウ重み** `use_shadow`：既定で無効。通常は不要です。重みの追加コピーを持ち、損失の急変時に現在の重みと混ぜるため、GPU メモリが増えます。

その他は上流と同じ `betas=(0.9, 0.995)`、`eps=1e-8`、`weight_decay=0.01` です。

**制約**

GPU は 1 基、勾配累積は `1`、混合精度は `bf16` または `no` を使ってください。累積と fp16 は EmoSens が読む損失値を変え、複数 GPU では異なる学習率が計算される可能性があるため、非対応です。

フォームはスケジューラとウォームアップを固定するため、設定は不要です。全体の勾配クリッピングは使えます。全パラメータに同じ学習率を使うため、LoRA+ は非対応です。U-Net／DiT とテキストエンコーダの個別学習率も実際の値を変えません。片方だけを学習する場合は、対応する学習対象の切り替えを使います。

**バージョン変更と再開**

[上流 v3.9.3 のコード](https://github.com/muooon/EmoSens/blob/e2c7bb3293baeb339a2d4a21f21ccbdc0260d3be/optimizer/emosens.py)を変更せずに使用しています。以前の v3.9.1 からパラメータは増えていません。主な変更は自動学習率の上限です。倍率 `0.1` と `1.0` の上限は、それぞれ従来どおり `3e-4` と `3e-3`。`1` より大きい倍率では上限が増えなくなりました。

再開時は、元の倍率、収束通知、シャドウ重みの設定を維持してください。保存状態からは完全に復元されません。旧バージョンの状態を再開した場合も、新しい上限規則を使います。

<!-- doc-anchor: loraplus -->
### LoRA+

Muon、Automagic3 を含む多くの方式で使えます。Prodigy、ProdigyPlus、EmoSens、LoRA-RITE、LoRA-Muon は非対応です。LoRA+ のグループ別学習率は、LoRA-RITE の A/B ペアと LoRA-Muon の共同更新に適合しません。AdaFactor は先に相対ステップを無効にする必要があります。

切り替え後は LoRA+ の倍率を再確認してください。Automagic3 では倍率適用後も `min_lr`〜`max_lr` に収まる必要があります。詳細は LoRA+ ガイドの「オプティマイザとスケジューラ」を参照してください。

<!-- doc-anchor: scenarios -->
## データセット別の目安

<!-- doc-anchor: one-image -->
### イラスト 1 枚

Anima は AdamW8bit、`1e-5`〜`2e-5` から始め、こまめに保存してください。SDXL は別の基準を使います。主なリスクは単一のポーズと構図の記憶です。StableAdamW は更新の急増を抑えますが、横顔、背面、別の表情を補えません。

<!-- doc-anchor: few-shot -->
### 2〜5 枚の少数画像

まず AdamW8bit の基準を作ります。出典が大きく異なる場合は CAME、損失や勾配が急増する場合は StableAdamW と比較します。短い学習では、内部スケジュールが十分に作用する前に終了する場合があります。

<!-- doc-anchor: galgame -->
### 美少女ゲームの表情差分

構図が固定されがちで、通常は AdamW8bit で始められます。方式の変更より表情のキャプションが重要です。固定背景や立ち姿をキャラクターの特徴として覚えさせないようにしてください。表情の枚数が極端に偏る場合は、CAME とも比較します。

<!-- doc-anchor: dmm-mixed -->
### DMM のカード・エフェクト・別キャラクターの混在

別キャラクター、文字、透かし、エフェクト、異なる形態を除くか、正確に記述してから AdamW8bit と CAME を比較します。まだログが不安定なら StableAdamW も比較します。どのキャラクターが学習対象かは、画像の整理とキャプションで示す必要があります。

<!-- doc-anchor: mixed-quality -->
### 品質が混在する画像

ぼけ、圧縮されたスクリーンショット、重複した切り抜き、連続する Live2D フレームを先に整理します。残す画像はキャプション、グループ、リピート回数で調整してください。勾配の急増が残る場合は、CAME または `percentile_clipping=99` を個別に試します。

<!-- doc-anchor: outfits-forms -->
### 複数の衣装・形態

正確な衣装・形態タグと、グループ別の適切なサンプリングが重要です。AdamW8bit、CAME、StableAdamW を使えます。1 枚の鮮明さだけでなく、衣装の制御、同一性の維持、形態の混ざり方を評価してください。

<!-- doc-anchor: style-lora -->
### 画風 LoRA

こちらも AdamW8bit から始めます。汎化には、被写体の多様性と、内容と画風を区別するキャプションが重要です。StableAdamW は異常なバッチの影響を抑えますが、強いクリッピングは少数の画風特徴も弱めます。

<!-- doc-anchor: vram -->
### VRAM が不足する場合

まず AdamW8bit か Lion8bit を使い、メモリ不足を確認してから Paged 版へ切り替えます。実際にページングすると、CPU–GPU の状態転送で遅くなる場合があります。小さなテンソルをわずかな節約のために量子化しないよう、`min_8bit_size=4096` を維持してください。

<!-- doc-anchor: starting-configs -->
## 無理のない開始設定

| 用途 | オプティマイザと設定 | その他 |
| --- | --- | --- |
| Anima の基準 | AdamW8bit、上表の学習率、`weight_decay=0.01` | constant、`max_grad_norm=1`、既定の rank/alpha、DiT のみ |
| Anima の混在データ比較 | CAME、上表の学習率、その他は既定値 | constant、`max_grad_norm=1`、固定条件で検証 |
| Anima の勾配急増対策の比較 | StableAdamW、上表の学習率、安定性項目は本ツールの既定値 | Kahan 有効、constant、`max_grad_norm=1` |
| Anima の LoRA-Muon 実験 | LoRA-Muon、上表の学習率、その他は既定値 | constant、`max_grad_norm=0`、UI 推奨の rank/alpha、まず学習率だけ変更 |
| Anima の Lion 実験 | Lion または Lion8bit、上表の学習率 | constant。Lion 公式の設定一式ではない |
| 弱い 8-bit クリッピング | 基準の AdamW8bit に `percentile_clipping=99` | 他は変更しない |

長すぎる学習は、繰り返すポーズ、背景、衣装をキャラクターと結び付ける場合があります。リピート回数だけでなく、実際の更新回数で短縮を判断してください。

| 条件 | リピート回数を減らした効果 |
| --- | --- |
| エポック数が固定 | 通常は画像の使用回数と更新回数が減る |
| 総ステップ数が固定 | 更新回数は直接減らない。バケット、シャッフル、サブセットの割合が変わる場合がある |
| 一部のサブセットだけ減らす | 他のサブセットに対する相対的な学習比重が変わる場合がある |

完全な累積区間の実効バッチサイズは、バッチサイズ × 勾配累積数 × GPU 数です。比較ではバッチと累積を固定し、バケット末尾や画像の組み合わせを変えないようにします。

過学習には、まず総学習時間の短縮や学習率の低下を検討します。複数の保存チェックポイントの生成画像を比べて、終了時点を選んでください。

<!-- doc-anchor: troubleshooting -->
## 症状別の確認

| 症状 | 先に確認する点 | 試す変更 |
| --- | --- | --- |
| 損失は横ばいだが画像が悪い | データ、キャプション、生成プロンプト、保存時点 | 通常は方式の変更が第一手ではない |
| 一時的な損失・勾配の急増が再現する | 対象のバッチ、画像、学習率 | StableAdamW、または `percentile_clipping=99` だけを比較 |
| NaN / Inf | すぐに停止し、学習率、精度、不正なデータ、再開地点を確認 | 原因を除いてから StableAdamW と比較。継続する問題をクリッピングで隠さない |
| 状態メモリが不足する | 解像度、バッチ、プレビューではなく状態が原因か | まず 8-bit、それでも不足するなら Paged |
| ポーズ・背景・衣装をすぐに記憶する | ステップ、リピート、学習率、重複画像 | 学習率を下げるか短縮する。方式の変更だけでは直りにくい |
| キャラクターの特徴が弱い | トリガーワード、キャプション、有効ステップ数、rank、学習対象 | 確認後に学習率を少し上げる |

<!-- doc-anchor: ab-testing -->
## 条件を揃えた比較

1. データセット、キャプション、シード、ベースモデル、VAE、rank/alpha、バッチ、総ステップ数を固定します。
2. 生成プロンプト、サンプラー設定、生成シードを固定します。
3. 上表から始め、方式ごとに使える学習率の範囲を探します。他の条件を固定し、学習率だけを変えます。
4. 同じステップのチェックポイントを比較し、勾配ノルム、ピーク VRAM、所要時間を記録します。
5. 損失だけでなく、再現性、衣装の制御、ポーズ・背景の固定化、プロンプトへの反応で判断します。

毎回同じベースモデルから始めてください。別のオプティマイザのモメンタム状態は、そのまま流用できません。

Prodigy、Muon、LoRA-Muon は更新の尺度が異なります。学習率を個別に調整し、同じ学習予算で比較してください。この比較は設定一式の比較になります。

<!-- doc-anchor: limits -->
## オプティマイザで対応できる範囲

オプティマイザは勾配を処理します。誤ったキャプションを見分けたり、低品質画像の重みを自動で下げたりはしません。ポーズや背景の記憶には、先にデータの多様性と終了時点を見直してください。

## よくある質問

**モデル種別やオプティマイザを変えると、学習率が変わるのはなぜですか？**

手動編集していない推奨値だけを置き換えます。手動の値、読み込んだ設定、カスタム値は維持します。

**Prodigy の学習率が `1.0` に固定されるのはなぜですか？**

Prodigy は学習率を倍率の基準として使う、D 適応型の方式です。sd-scripts が `1.0` 付近を推奨するため、UI で固定し、理由を表示します。

**生成設定で StableAdamW の重み減衰が `0` になるのはなぜですか？**

パッケージの `0.01` を、本ツールが明示的に `0` へ上書きします。AdamW8bit は `0.01` のままです。方式だけの違いを比べる場合は、減衰も揃えてください。

**切り替え後に LoRA+ が無効になるのはなぜですか？**

Prodigy、ProdigyPlus、EmoSens、LoRA-RITE、LoRA-Muon は非対応です。AdaFactor は `relative_step` と `warmup_init` の両方を無効にする必要があります。UI に理由を表示し、バックエンドも非対応の組み合わせを拒否します。

**結果が悪いとき、方式の変更とデータ確認のどちらを先にしますか？**

先にデータ、キャプション、リピート、学習率、終了時点を確認します。オプティマイザは主に収束速度、状態メモリ、数値安定性に作用し、キャラクターの再現性を決める主因ではないことが多いためです。
