# 训练集诊断

训练集诊断汇总训练时写入的逐样本日志 `loss.jsonl`，按**同噪声区间的相对残差**和**每 Epoch 斜率**统计每张图片与各个分组的表现，用于排查图文不符、异常原图或子集与分桶偏差。

适用训练类型：**SDXL**、**Anima**、**MOSS-Image**。Krea 2（`musubi-tuner`）暂未记录 `loss.jsonl`。

残差与斜率比较的是**同一次训练内部**不同图片之间的相对难易程度；整体收敛质量仍需结合多个模型存档的生成预览评估。

## 残差：按相近噪声水平横向比较

训练每一步都会为样本随机抽取一个噪声时间步。样本的原始 Loss 随时间步（噪声强度）变化很大：例如在某一时间步下所有图片的 Loss 都在 `0.35` 左右，在另一时间步下都在 `0.15` 左右。此时 `0.30` 的 Loss 在后者偏高，在前者反而偏低。某张图片可能只是碰巧多抽到了几个高 Loss 的时间步，原始均 Loss 就会显得偏高，因此原始 Loss 无法直接用于跨样本或跨图片比较。

诊断工具使用**残差（Residual）**来衡量“与相近噪声水平的其他样本相比，这次的 Loss 高出或低于平均水平多少”：

1. 将当前记录的时间步范围等分为 **10 个时间步区间**，先求出每个区间内所有样本的平均 Loss。
2. 按以下公式计算每次采样的残差，再对同一张图片（或同一分组）的所有可比较采样取平均：

<div class="doc-equation" role="group" aria-label="单次采样残差公式">
  <div class="doc-equation-kicker">单次采样残差</div>
  <div class="doc-equation-expression">残差 = 单次 Loss ÷ 所在时间步区间均 Loss − 1</div>
  <p>单张图片或单个分组的“残差”为其所有可比较采样残差的平均值。</p>
</div>

| 残差值 | 含义 |
| --- | --- |
| `0%` | 与同噪声区间下的全集平均水平一致 |
| `+50%` | 比同噪声区间下的平均水平高 50%（相对更难） |
| `-20%` | 比同噪声区间下的平均水平低 20%（相对更易） |

例如某时间步区间的全局均 Loss 为 `0.20`，某张图落在该区间的某次采样 Loss 为 `0.30`，则该次残差为 `0.30 ÷ 0.20 - 1 = +50%`。

某个时间步区间内需包含至少 2 张不同图片才能构成同噪声参照。缺少时间步或所在区间仅有当前图片自身的采样，只计入“原始均 Loss”和总采样次数；可比较采样次数未达到顶部“最少采样”设定值时，图片状态会标记为`采样不足`或`参照不足`。

## 斜率：结合多轮变化趋势判断

构图复杂、生僻特征或与底模先验差距较大的图片，训练初期的残差通常会高于平均水平；随着模型逐步学会这些特征，残差会按轮次下降。多轮训练后残差依然居高不下时，通常提示图片或标注本身存在冲突。

当同一张图片在**至少 3 个 Epoch** 都有可比较采样时，工具会先算出该图在各 Epoch 的平均残差，再用最小二乘法拟合出**每 Epoch 斜率（Slope）**，即每经过 1 个 Epoch 的残差变化量（仅 2 个 Epoch 时随机波动过大，暂不计算斜率）。
- 例如某张图的平均残差从 Epoch 1 的 `+30%` 降到 Epoch 3 的 `+20%`，每 Epoch 斜率约为 `-5.0%`。

结合**残差**与**斜率**的排查参考：

| 观察到的情况 | 常见原因 | 排查与处理 |
| --- | --- | --- |
| 残差偏高（`≥ +20%`），但斜率持续为负（`≤ -2.0%` / Epoch） | 画面较复杂或偏离底模先验，模型正在吸收该特征 | 保留图片，继续观察后续 Epoch 走势 |
| 残差偏高（`≥ +20%`），且斜率平缓或上升（`> -2.0%` / Epoch） | 标注漏标或错标、图文不符、裁切失当、画质受损，或与数据集其他图片的特征定义冲突 | **打开单图详情核对**原图与标注文本，可在标签编辑器中修正 |
| 残差长期明显偏低（`≤ -20%`） | 背景单调、特征简单，或数据集中存在重复/高度相似的图片 | 少量属正常；若大批图片长期极低，结合预览图留意过拟合 |
| 采样次数较少或未满 3 个 Epoch | 每张图每个 Epoch 只会以随机时间步和随机噪声训练 `1 × repeats` 次，样本少时残差受随机波动影响较大 | 调高顶部**最少采样**，或等待满 3 个 Epoch 后再判断 |

## 界面配合与排查步骤

1. **优先检查 `NaN / Inf` 异常**
   - 记录过非有限（`NaN` / `Inf`）Loss 的图片会自动置顶，并在详情弹窗顶部标出首次异常出现的 `Epoch`、`Step` 与时间步 `t`。
   - 异常集中在个别图片时，检查原图文件是否损坏、通道位深或色彩空间是否异常；多张图普遍出现时，检查学习率、混合精度与数值稳定项配置。

2. **展开“分布与分组”定位整体偏差**
   - **逐图分布图**：未满 3 个 Epoch 时显示残差分布直方图与单图散点；满 3 个 Epoch 后切换为“横轴残差 × 纵轴斜率”散点图，右上角高亮区即为高残差且下降缓慢或未下降的待查样本。悬停圆点可预览缩略图与指标，点击直接打开单图详情。
   - **噪声区间图（`1000 → 0`）**：按去噪顺序从左（`1000`，高噪声）到右（`0`，低噪声）展示全集在 10 个时间步区间的平均 Loss 基准，以及高（`1000–667`）、中（`667–333`）、低（`333–0`）三段噪声的采样次数与占比。残差以各区间均值为基准计算；若某段噪声总采样极少，该区间的残差波动也会更大。
   - **分组对比**：点击**分桶尺寸**、**子集**或**目录**中的任意一行，可直接过滤下方图片列表。某一分桶尺寸整体残差偏高时，重点检查该长宽比下的裁切与缩放；某一子集或目录整体偏高时，检查其 `num_repeats`、`class_tokens` 或标注质量。**批次大小**仅用于对比不同批大小（如分桶末尾批）的整体均值。

3. **单图详情核对与改标**
   - 点击任意图片打开详情弹窗，右侧依次展示高/中/低噪声区间的单图残差、**各 Epoch 残差走势**折线，以及**各时间步 Loss 对照**（将本图历次采样点叠在全集均 Loss 基准线上，便于分辨是全噪声段普遍偏高，还是仅在某一次采样中偶然偏离；查看各区间残差时请结合该区间的采样次数）。
   - 弹窗底部按子集配置自动读取对应的标注文件、元数据标注或 `class_tokens`。若标注来自独立的本地单文件，可直接点击**在标签编辑器中打开**跳转修改。

4. **切换记录段与筛选正则图片**
   - **记录段**：使用相同输出目录和输出名称再次启动训练时，`loss.jsonl` 会在原文件末尾追加新的 `run_id` 记录段。**断点续训**时，可在顶部选择**合并全部记录**以跨段连续统计采样次数与斜率；**使用同名重新从头训练**时，应保持默认的**最新**记录段，避免混入旧训练的数据。
   - **正则图片**：包含正则化样本时，列表工具栏支持切换**含正则图片 / 不含正则图片 / 仅正则图片**，便于将训练图与正则图分开对比。

## 状态分类规则与日志口径

### 界面状态分类条件

上游 `analyze_run_loss.py` 仅按残差高低排序；本界面按顶部**最少采样**（默认 `≥ 3` 次可比较采样）将图片归为以下状态，其中筛选栏的 **`高残差待查`** 汇总了三种高残差状态：

| 筛选分类 | 卡片 / 表格状态徽章 | 判定条件（自上而下优先匹配） |
| --- | --- | --- |
| `NaN / Inf` | `NaN / Inf` | 记录过至少 1 次非有限（`NaN` / `Inf`）Loss |
| — | `采样不足` | 有限 Loss 总采样次数 `< 最少采样` |
| — | `参照不足` | 总采样达标，但同时间步区间有其他图片可参照的采样次数 `< 最少采样` |
| `高残差待查` | `高残差待查` | 可比较采样达标，残差 `≥ +20%`，且尚不足 3 个可比较 Epoch（未算出斜率） |
| `高残差待查` | `高残差未下降` | 可比较采样达标，残差 `≥ +20%`，且斜率 `≥ 0%` / Epoch |
| `高残差待查` | `高残差下降慢` | 可比较采样达标，残差 `≥ +20%`，且斜率位于 `-2.0%` 至 `0%` / Epoch 之间 |
| `高残差下降中` | `高残差下降中` | 可比较采样达标，残差 `≥ +20%`，且斜率 `≤ -2.0%` / Epoch |
| `低于均值` | `低于均值` | 可比较采样达标，且残差 `≤ -20%` |
| — | `接近均值` | 可比较采样达标，且残差位于 `-20%` 至 `+20%` 之间 |

### `loss.jsonl` 记录口径

- **已计入的权重**：单个样本在像素或 Token 上的平均预测误差，已包含模型基于时间步的 Loss 权重（`--weighting_scheme`，参见[时间步](timesteps.zh-CN.md#weighting)）以及 masked loss 权重（启用时）。
- **未计入的权重**：样本级 `loss_weight`（如正则化图片的 `--prior_loss_weight`）及其后施加的 Loss 重加权（如 `--min_snr_gamma`）不计入 `loss` 字段。
- **刷盘间隔与多卡训练**：每隔约 5 秒随 `status.json` 批量写入磁盘（进程被强制终止时可能缺失最后几步）；多卡分布式训练下仅记录主进程（rank 0）处理的样本。
